# BRIS Logistics — переносимый прототип 0.2

Это проект для проверки интерфейса и последующей разработки, а не готовая система для выдачи окончательных цен клиентам.

## Запуск на Windows

1. Установите Python 3.10 или новее, если его нет. При установке включите добавление Python в PATH.
2. Распакуйте архив в отдельную папку, например `C:\projects\bris-logistics`.
3. Запустите `start_windows.bat`. Откроется браузер с приложением.
4. Для остановки нажмите Ctrl+C в консоли.

На Linux: `python3 app.py --no-browser`. По умолчанию адрес `http://127.0.0.1:8765`.
Зависимости pip для этой версии не нужны. Прямое открытие `web/index.html` показывает интерфейс без серверной базы.

## Уже работает

- Первичные поля инвойса, маршрута и контейнеров.
- Ручные валюты/курсы и демонстрационный расчёт в USD.
- Ввод расходов со своей валютой, курсом и количеством.
- Справочники ставок и контактов в снимке расчёта.
- Подготовка текста запроса ставки и журнал черновиков, без отправки.
- Три HTML печатные формы: товар с доставкой, логистика, внутренний расчёт.
- Сохранение PDF через печать браузера.
- SQLite: сохранение версий, список, поиск, открытие и копирование.
- Каждая версия хранит исходные поля, ставки, курсы, результат, справочники на момент сохранения и версию демонстрационной формулы.

## Ограничения

- Формулы демонстрационные, не перенесены один в один из действующего Streamlit-калькулятора. Нельзя считать их утверждённой моделью.
- Курсы не загружаются автоматически. Примеры курсов при смене валюты требуют проверки.
- Таможенные ставки/НДС введены как редактируемые примеры; юридическая актуальность не проверена.
- Incoterms пока не меняет формулы автоматически.
- Кнопка загрузки выбирает файл, но не распознаёт и не сохраняет его в базе.
- Почта не отправляется и не принимается; поля почтовых секретов ещё не реализованы.
- Справочники пока сохраняются внутри версии расчёта; отдельные общие таблицы поставщиков/предложений будут следующим этапом.
- Существующие печатные формы из рабочего приложения ещё надо сверить с этими макетами.
- Это локальный однопользовательский запуск, не публичный веб-сервис.

## Где данные

При первом запуске создаётся `data/bris.sqlite3`. Эту папку нельзя коммитить в GitHub: `.gitignore` уже добавлен.
Для переноса истории остановите приложение и перенесите папку `data` вместе с проектом. Для резервной копии также сначала остановите приложение.
Путь можно изменить переменной окружения `BRIS_DATA_DIR`.

## Разработка на сервере

Храните проект отдельной папкой от текущего сайта. На Windows-сервере пока запускайте из локальной сессии / RDP и открывайте localhost.
Для работы через интернет понадобится отдельная настройка: вход пользователей, права, HTTPS, серверное хранение секретов и производственный сервер приложения. Не открывайте порт этого прототипа наружу.

Дальнейшая архитектура: Python API + общая утверждённая расчётная модель + PostgreSQL + web-интерфейс. Текущий SQLite подходит для проверки и локального пилота.

## GitHub

Хранить код удобнее в приватном репозитории GitHub, а архив на Google Диске использовать для передачи и резервной копии исходников.
На момент подготовки архив не загружен в публичный `alexsvetlit-wq/logistics-bris`.
Закрытие репозитория не закрывает автоматически работающий сайт Streamlit. Доступ к сайту регулируется отдельно.
Не добавляйте в git базу, клиентские инвойсы, письма, ставки или почтовые пароли.
